# 0004. Laya as a fine-tuned router candidate only

- Status: proposed
- Date: 2026-09-26

## Context
Laya (Apache-2.0, v0.3.20, pre-1.0) is an encoder classifier, not a generator. Its multilingual checkpoint is mmBERT-base with 322M parameters. Self-reported numbers:
- zero-shot MASSIVE intent (20 options): es 0.53, pt 0.45
- banking77: 0.425 (authors: keep under ~20 options)
- jailbreak detection: 0.71-0.76; moderation "barely above chance"
- CPU: 193-464 ms per request, 7-10 s cold load

The multilingual checkpoint "ships with no fitted temperatures at all". The authors call it "a fast base to specialise, not a zero-shot decision engine".

## Decision
- Zero-shot router: no.
- **Router candidate after fine-tuning** on our labels (customer and time splits), with temperature fitted on `val`: yes, as one rung of the L1 ladder (keywords → TF-IDF + LR → plain fine-tuned multilingual encoder → Laya → LLM zero-shot). It must beat the plain fine-tuned encoder to justify the dependency.
- Guardrail: at most an extra signal, never the control; security comes from the tool layer.
- Judge: no. Grading needs checks against records and policy.

## Consequences
- Deployment needs a memory and latency sizing test (fp32 is roughly 1.3 GB; try ONNX int8).
