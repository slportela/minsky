# PR 51 demo redeploy (2026-10-06)

PR [#51](https://github.com/slportela/minsky/pull/51), the opt-in agentic dispute search (ADR 0017), was merged
to `main` as `17101acc48d72f46756fd7cb39926766cafac4ac` and deployed with
`infra/smoke_vm.sh deploy 17101acc48d72f46756fd7cb39926766cafac4ac`, run by the owner from their workstation.
The release it replaced was `b3dfe2d56a05` (the PR 66 restyle). The PR had no review recorded on GitHub when it
was merged.

## What the release changes

The release changes `backend` and `prompts` (22 files, +3362/-15 from `b3dfe2d56a05`), `frontend` (6 files, +128/-3)
and `compose.yaml` (two lines: `MINSKY_AGENT_MODE` and `MINSKY_ALLOW_MODE_SWITCH`). With the defaults the demo
behaves as before: `MINSKY_AGENT_MODE=workflow` and `MINSKY_ALLOW_MODE_SWITCH=false`, so `GET /api/chat/options`
answers `mode_switch: false`, the chat page shows no flow selector and no beta notice, and the backend ignores a
`mode` sent by hand. **The deploy does not touch `runtime.env`**, so it did not turn the switch on. Opening the
beta needs `MINSKY_ALLOW_MODE_SWITCH=true` in the VM's `runtime.env` and a recreated API container, which only the
owner does.

## Enabling the beta switch (owner, after the deploy)

The owner entered the VM over SSH with temporary Lightsail credentials, checked that `runtime.env` had no
`MINSKY_ALLOW_MODE_SWITCH` line (0 matches), appended `MINSKY_ALLOW_MODE_SWITCH=true` (1 match afterwards, value
`true`) and ran `docker compose -p minsky ... up -d` with the three env files. Compose reported
`minsky-api-1 Started`, with `web`, `postgres` and `caddy` unchanged. The API container showed
`Up 40 seconds (healthy)`. From outside, `GET /api/chat/options` on the public URL answered
`{"mode_switch":true,"mode":"workflow"}`: the switch is on and the default flow is still the workflow. To undo it,
remove that line and run the same compose command again. The temporary SSH credentials were kept in a private
temporary directory on the owner's workstation and deleted afterwards.

beta notice are shown, and the chat works. Which flow, which demo credential and which customer were used, and
what was typed, were not recorded, so this is not a record of a specific conversation.

Not checked for this release, or not recorded: a demo operator login, a staff login, and whether the agentic flow

live only in the eval harness (SQLite fixture worlds) and by hand in a local stack. No cases were reset, no demo
credentials were edited (only the one flag line was added to `runtime.env`) and no volumes were removed. The model
provider of the runs above was reached directly with the interim OpenAI configuration; the demo's own provider
setting was not changed by this deploy. In-memory conversations were lost when the API container was recreated.
