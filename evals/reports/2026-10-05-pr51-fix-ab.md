## A coverage correction

An earlier message said no dev case declines the offer of a person after the limit. The case
`dispute-offer-declined-then-dispute-es` does exist, but the agentic customer never replayed it: it answered the
card with two plain yeses and the dispute opened without reaching the ambiguous replies, the offer or the refusal.
That case therefore passing in agentic mode said nothing about the fix. The reactive customer now replays that
sequence when `known_info.declines_person_offer` is `"true"`, and the new case
`dispute-decline-person-then-search-es` carries it. Offline (scripted agent, no model) it passes with the fix and
**fails without it** (`outcome: expected resolve, observed clarify`), so it detects the bug. It has not been run
live when this report was first written; both full runs above predate the case. It was then run live (next section).

## Live run of the new case (`dispute-decline-person-then-search-es`, commit 5b4b118)

Both modes, 3 trials, 2 workers, one case, clean `5b4b118`: **workflow 3/3 and agentic 3/3** (Wilson 95% CI 43.8–100.0% each),
0/3 infrastructure errors in both. Run folders `smoke-1a26673f6c64` (workflow) and `smoke-36fe88d9cd60` (agentic).
Every transcript was read for the first trial of each mode and the user turns of all six match the script:
three replies in words, an offer of a person, "no", the charge again, then two plain yeses and a dispute opened.
In the agentic transcripts the message after the refusal is searched and the card shown, not answered with a second
offer, which is what the reset fixes (offline, the case fails without it). Usage USD 0.0050573 (agentic) and
USD 0.0030918 (workflow); reservations USD 0.0532014 and USD 0.0410527. Three trials per mode cannot show
reliability; this is a regression check for one path, not a rate. The fix changes only agentic-mode code
(`unclear_detours` is not used by the workflow), so the workflow run is a control, not a check of the fix.
