## Provider failures found and repaired

The **unmodified** `2213a31` baseline could not run: 33/33 attempted trials failed with HTTP 400
`invalid_json_schema`. Pydantic generated a Decimal string pattern with regex lookaround, which
the provider rejected before extraction. Those attempts are configuration errors, not scored
agent failures. A separate one-call diagnostic retained the provider's sanitized error evidence.

An initial compatibility fix removed that pattern but allowed arbitrary strings in the remote
schema. Its first corrected run passed 35/36; one extraction returned `25.00 USD`, which local
Decimal validation correctly rejected. The final schema admits a JSON number or a numeric string
matching `^[+-]?[0-9]+([.][0-9]+)?$`. It retains local Decimal validation and monetary precision,
and disallows currency suffixes without unsupported regex features. The mock HTTP regression
failed before the fix and passed after; a new dev case distinguishes 25.37 from 25.38.

The scored baseline is explicitly **`2213a31` plus only the final amount-schema compatibility
change**; it is not claimed to be the untouched historical commit. Backend source, prompts,
case hashes, model IDs, calls, requests, tool evidence, audit and grades are retained separately
from the harness checkout SHA. All 36 completed corrected model calls reported `gpt-6-luna`.

These are draft dev scripts with three implemented safety checks: ownership, explicit action
confirmation and verified action claims. Grounding, language and injection graders remain
unsupported; Portuguese, held-out evaluation and the full L2 strategy remain pending. Repeated
trials are descriptive evidence, not independent coverage of all customer behavior. SQLite L2
does not establish production PostgreSQL behavior or durable case storage.

Rates use the [official GPT-6 Luna Standard short-context prices](https://developers.openai.com/api/docs/models/gpt-6-luna):
USD 0.10 input and USD 0.50 output per million tokens. Accounting conservatively prices all input
as uncached, disables SDK retries and retains reservations when usage is unavailable. Across
all attempts and integrated browser checks, reported usage prices total **USD 0.0124252**;
conservative reservations total **USD 0.2085836**, within the approved USD 1. Failed-call usage
is unknown, and these amounts are not an invoice.
